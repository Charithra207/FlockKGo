# Deploying FlockGo (free tier)

**Current deployment**

| Piece | Where | Address |
|---|---|---|
| Frontend | Vercel (project `flock-k-go`) | https://flock-k-go.vercel.app |
| API | Render web service `packvote-api` | https://packvote-api-nmz2.onrender.com |
| Database | Neon Postgres, Singapore | (connection string lives in Render's `DATABASE_URL`) |

All three are free. Render's free server sleeps after 15 minutes idle and takes about 50 s to wake. Two things handle that:
- **Wake-up ping:** the site pings `/health` as soon as anyone opens it.
- **Keep-awake job:** `.github/workflows/keep-api-awake.yml` pings it every 10 minutes.

The ML analysis runs inside the API (`USE_CELERY=false`), so no Redis or worker is needed.

**Updating the live site:** push to `main`. Vercel and Render both redeploy on their own.

## Setting it up from scratch

### 1. Database (Neon)
1. Create a project at neon.tech in the **Singapore** or **Mumbai** region. Only "Postgres database" needs to be on.
2. Choose **Connect**, turn **off** connection pooling, and copy the `postgresql://…` string.

### 2. API (Render)
1. Generate an admin secret:
   ```
   python -c "import secrets; print(secrets.token_hex(32))"
   ```
2. In Render, choose **New → Blueprint**, pick this repo on branch `main`. It reads `render.yaml`.
3. Fill in the environment variables:

   | Key | Value |
   |---|---|
   | `DATABASE_URL` | the Neon string |
   | `API_SECRET_KEY` | the secret from step 1 |
   | `FRONTEND_BASE_URL` | your Vercel URL (use `http://localhost` until you have it) |
   | `ADMIN_EMAILS` | the email you'll log in with (makes you admin) |
   | `OPENAI_API_KEY` | optional, can be empty |
   | `AUTH_TOKEN_SECRET` | generated by Render automatically |

4. Deploy. Every start runs `build.sh`, which:
   - creates or upgrades the tables (`db_bootstrap.py`)
   - seeds the 65 Karnataka destinations
   - loads the 619 spots from `backend/data/`

   It's safe to rerun: nothing is duplicated, and spots you've edited as admin are never overwritten.
5. Check that `https://<service>.onrender.com/health` returns `{"status":"alive"}`.

Render may add letters to the service name (ours became `packvote-api-nmz2`). Always use the exact address shown on the service page.

### 3. Site API key
In production the API needs an `X-API-Key` from the website. Create one:
```
curl -X POST https://<service>.onrender.com/v1/admin/api-keys \
     -H "X-Admin-Secret: <API_SECRET_KEY>" \
     -H "Content-Type: application/json" -d '{"name":"web"}'
```
Copy the key from the response.

If the response is `Invalid admin secret`, the header doesn't match Render's `API_SECRET_KEY` exactly. Copy the value from Render → **Environment** (eye icon), with no spaces or `< >`.

The first call after the server has been idle can take about a minute; that's just the wake-up.

### 4. Frontend (Vercel)
1. **Add New → Project**, import the repo, set **Root Directory** to `frontend`. The preset is **Vite**; leave the build settings at their defaults.
2. Add these environment variables:

   | Key | Value |
   |---|---|
   | `VITE_API_URL` | `https://<service>.onrender.com/v1` |
   | `VITE_API_KEY` | the key from step 3 |

3. Deploy, then set Render's `FRONTEND_BASE_URL` to the Vercel URL (no trailing `/`).

`VITE_*` values are baked in at build time. After changing one in Vercel, go to **Deployments → ⋯ → Redeploy**.

### 5. Keep-awake job
On GitHub, go to **Actions → Keep API awake → Run workflow** once. After that it runs every 10 minutes.

GitHub pauses scheduled jobs after 60 days with no commits; re-enable it from the same page if that happens. If your API address changes, update the URL in `.github/workflows/keep-api-awake.yml` and in `frontend/.env.production`.

### 6. Make yourself an admin
1. In Render, open **packvote-api → Environment**, add `ADMIN_EMAILS` = the email you'll log in with, and click **Save, rebuild, and deploy**. For more than one admin, separate the emails with commas.
2. On the site, click **Log in** (top right) and sign up with that email, or log in if you already have an account.
3. An **Admin** link appears in the top bar. It opens `/admin/spots`, the review queue.

No Render Shell is needed. If you'd rather run the script on your own computer, set `DATABASE_URL` to the Neon string and run `python make_admin.py you@example.com` from `backend/`.

## 7. Optional features (each switches on when you add its key)

All of these are off until you set them, and the site works fine without them. Add server keys in
**Render → packvote-api → Environment**, then click **Save, rebuild, and deploy**.
`GET /v1/auth/config` on the API shows which ones are on.

| Feature | Render keys | Where to get them | Cost |
|---|---|---|---|
| Password-reset + verification emails | `RESEND_API_KEY`, `MAIL_FROM` | resend.com | free: 3,000/month |
| Sign in with Google | `GOOGLE_CLIENT_ID` | Google Cloud console | free |
| "I'm human" check on sign-up and sharing | `TURNSTILE_SECRET`, `TURNSTILE_SITE_KEY` | Cloudflare Turnstile | free |
| Error tracking | `SENTRY_DSN` (Render) + `VITE_SENTRY_DSN` (Vercel) | sentry.io | free tier |
| Page-view analytics | none | Vercel → project → **Analytics → Enable** | free on Hobby |
| Only verified emails can share spots | `REQUIRE_EMAIL_VERIFICATION=true` | turn on after email works | |

### Email (Resend)
1. Sign up at resend.com → **API Keys → Create** → copy the key into `RESEND_API_KEY`.
2. Until you verify a domain, Resend only delivers to **your own sign-up email**. For testing, leave `MAIL_FROM` unset (it defaults to `FlockGo <onboarding@resend.dev>`).
3. To email everyone: **Domains → Add domain**, add the DNS records it shows, then set `MAIL_FROM` to e.g. `FlockGo <hello@yourdomain.com>`.
4. Without email, admins can still make a password-reset link at `/admin/spots` (bottom of the page) and send it on WhatsApp.

SMTP works instead of Resend: set `SMTP_HOST`, `SMTP_PORT` (587), `SMTP_USER`, `SMTP_PASSWORD`, `MAIL_FROM`.

### Google sign-in
1. console.cloud.google.com → create a project → **APIs & Services → OAuth consent screen**: External, app name FlockGo, your support email, then **Publish app**.
2. **Credentials → Create credentials → OAuth client ID** → type **Web application**.
3. **Authorised JavaScript origins**: `https://flock-k-go.vercel.app` (and `http://localhost:5173` for local testing). No redirect URI is needed.
4. Copy the **Client ID** (ends in `.apps.googleusercontent.com`) into `GOOGLE_CLIENT_ID` on Render. The website picks it up from the API automatically.

### Captcha (Cloudflare Turnstile)
1. dash.cloudflare.com (free account) → **Turnstile → Add widget**, domain `flock-k-go.vercel.app`, mode **Managed**.
2. Copy the **Site key** into `TURNSTILE_SITE_KEY` and the **Secret key** into `TURNSTILE_SECRET` on Render.
3. A hidden honeypot field already blocks simple bots even without this.

### Error tracking (Sentry)
1. sentry.io → create two projects: **FastAPI** and **React**.
2. FastAPI project DSN → `SENTRY_DSN` on Render. React project DSN → `VITE_SENTRY_DSN` on Vercel, then **Redeploy**.
3. Reports don't include emails or IP addresses.

### Analytics (Vercel)
Vercel → your project → **Analytics** tab → **Enable**. The code is already in the site; nothing else to set.

## Installable app + link previews (already on)
- **Installable app:** on a phone, open the site → browser menu → **Add to Home screen**. Spots, profiles and map areas you've opened keep working offline. After a deploy, the new version loads on the next visit.
- **Link previews:** links to `/spots/…`, `/u/…` and `/u/…/wrapped` show a title, description and image on WhatsApp, Instagram, X, Telegram and Slack (`frontend/api/og.js`, routed by user agent in `frontend/vercel.json`).

## Refreshing the spot data

The spots in `backend/data/*.json` load automatically on every deploy. To refresh them from OpenStreetMap, run these locally, then commit the JSON files:
```
cd backend
python import_osm_spots.py fetch --kind cafe
python import_osm_spots.py fetch --kind nature --max-hidden 100
```

Refreshing from Wikidata also needs `WIKIMEDIA_CONTACT` set to a contact address or URL, as their robot policy requires.

## Troubleshooting

| Symptom | Fix |
|---|---|
| `timeout` / "server is waking up" | Normal after idle on the free plan; retry. Check the keep-awake job is enabled. |
| `Auth error (401/403) … API key` | `VITE_API_KEY` in Vercel is missing or wrong. Fix it, then redeploy. |
| Blocked by CORS in the browser console | Set `FRONTEND_BASE_URL` on Render to the exact Vercel URL. |
| Render deploy fails | Open the service's **Logs**, and check that `DATABASE_URL` is set and starts with `postgresql://`. |
| Google button doesn't appear | `GOOGLE_CLIENT_ID` missing on Render, or the site's address isn't in the OAuth client's **Authorised JavaScript origins**. |
| Reset emails not arriving | Without a verified domain, Resend only sends to your own address. Check spam, or use the admin reset-link tool. |
| Old version still showing after a deploy | The installable app caches the shell: close all tabs of the site and reopen it (or pull to refresh twice). |
| Map is empty | Open `https://<service>.onrender.com/v1/spots/meta`; if counts are 0, check the deploy logs for the `import_osm_spots.py load` step. |
